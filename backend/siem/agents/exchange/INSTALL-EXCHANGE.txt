SENTRA SIEM - EXCHANGE SERVER (ON-PREMISES) LOG FORWARDING
Instructions for Exchange administrators                                    version 1.0 (2026-10)
===================================================================================================

WHAT GETS SENT, AND HOW
  Part 1  Admin audit      Windows event log "MSExchange Management" (which cmdlets were run in EAC / EMS,
                           by whom, with which parameters)         -> standard Windows agent (SentraAgent)
  Part 2  Message tracking %ExchangeInstallPath%TransportRoles\Logs\MessageTracking\MSGTRK*.log
          IIS web logs     C:\inetpub\logs\LogFiles\W3SVC1 and W3SVC2 (OWA, ECP, EWS, Autodiscover, MAPI,
                           ActiveSync, PowerShell)                   -> Exchange file shipper (SentraExchangeShipper)

  Both run on EACH Exchange server (mailbox / edge) as a scheduled task under SYSTEM, once per minute, and POST
  gzip-compressed batches over HTTPS to the SIEM collector. Nothing listens on the server; no inbound port is
  needed. Both use the SAME source id and the SAME token ("win-exchange"), so the SIEM shows one source per
  Exchange estate with every server as a host.

PRIVACY (PDPL)
  Mail subjects are NEVER stored in clear by the SIEM: the engine replaces the subject of every message
  tracking line with its SHA-256 hash before storing it (so identical subjects can still be correlated).
  Mail bodies are never read - message tracking only contains envelope data (sender, recipients, size, result).
  If the privacy review prefers not to send subjects at all, disable subject logging at the source:
      Set-TransportService <SERVER> -MessageTrackingLogSubjectLoggingEnabled $false
  (this is an Exchange setting; the SIEM works either way).

PREREQUISITES
  - Windows Server 2012 R2 or later, Windows PowerShell 5.1 (standard on Exchange 2016/2019/SE). No modules,
    no downloads, no third-party binaries.
  - Outbound TCP 443 from each Exchange server to the SIEM collector:
        10.0.0.10  (soc.example.com)
    through any firewall / proxy in between (the agent supports an explicit proxy in config.json: "Proxy").
  - The collector certificate must be trusted by the server (internal CA in Local Computer -> Trusted Root
    Certification Authorities; usually already pushed by GPO). Certificate validation is never disabled.
  - Message tracking enabled (default) and IIS logging enabled in W3C format for "Default Web Site" (W3SVC1)
    and "Exchange Back End" (W3SVC2) - the Exchange defaults. Recommended behind a load balancer: add the
    field X-Forwarded-For in IIS Manager -> Logging -> Select Fields -> Add Field, on both sites.
  - The ingest token for source "win-exchange" (from the SOC: on the SIEM  sudo sentra-siem-token show win-exchange).
    Put it in a text file on a share readable only by the admin running the install, or type it when prompted
    (hidden). Never pass it on the command line.
  - Run everything from an ELEVATED Windows PowerShell prompt (Run as Administrator), one server at a time or
    via your deployment tool.

FILES (copy the folders agents\windows and agents\exchange from the SOC package to C:\temp\ash on the server)
  agents\windows\sentra-agent.ps1, install-agent.ps1, uninstall-agent.ps1                     (Part 1)
  agents\exchange\sentra-exchange-shipper.ps1, install-exchange-shipper.ps1, uninstall-exchange-shipper.ps1 (Part 2)

---------------------------------------------------------------------------------------------------
PART 1 - ADMIN AUDIT: the standard Windows agent
---------------------------------------------------------------------------------------------------
The Windows agent forwards the Exchange admin audit channel "MSExchange Management" (event 1 = cmdlet
succeeded, 6 = cmdlet failed) by default, plus Security / System / Application errors / PowerShell 4104 /
Defender / Sysmon (if installed). Nothing Exchange-specific has to be configured.

  cd C:\temp\sentra\agents\windows
  .\install-agent.ps1 -CollectorUrl https://10.0.0.10 -SourceId win-exchange -TokenFile C:\temp\sentra\win-exchange.token

  (without -TokenFile the installer prompts for the token, hidden)
  Options: -SetLogSizes (Security log 1 GB so it buffers outages), -PinnedThumbprint <sha256>, -Loop, -NoStart.

If the Windows agent is ALREADY installed on the server from an earlier roll-out (before the Exchange channel
was in the defaults), add the channel to C:\ProgramData\SentraAgent\config.json -> "Channels":
  {"Name":"MSExchange Management","Enabled":true,"IncludeMessage":true,"Levels":[],"ExcludeEventIds":[],"EventIds":[1,6]}
and keep the SourceId it was installed with (re-running install-agent.ps1 keeps config, token and bookmarks).

Verify Part 1:
  Get-Content C:\ProgramData\SentraAgent\logs\agent.log -Tail 5       -> one "pass done:" line per minute
  schtasks /Query /TN SentraAgent                                     -> Ready / Running
  On the SIEM: Sources -> win-exchange -> this host appears (heartbeat within 5 minutes); run any harmless
  cmdlet in EMS (e.g. Get-MailboxDatabase) and it shows up as action "exchange-cmdlet".

---------------------------------------------------------------------------------------------------
PART 2 - MESSAGE TRACKING + IIS: the Exchange file shipper
---------------------------------------------------------------------------------------------------
  cd C:\temp\sentra\agents\exchange
  .\install-exchange-shipper.ps1 -CollectorUrl https://10.0.0.10 -SourceId win-exchange -TokenFile C:\temp\sentra\win-exchange.token

  (same token as Part 1; without -TokenFile the installer prompts for it, hidden)
  Options: -ExchangeInstallPath "D:\Exchange Server\V15"  (only if auto-detection via $env:ExchangeInstallPath /
           registry fails), -ServerName (defaults to the computer name), -PinnedThumbprint, -Loop, -NoStart,
           -ResetConfig.

The installer
  - copies the shipper to C:\Program Files\SentraExchangeShipper
  - creates C:\ProgramData\SentraExchangeShipper (ACL: SYSTEM + Administrators only) with config.json, token.txt,
    bookmarks.json, state.json, queue\, logs\shipper.log (5 MB x 3)
  - registers the scheduled task \SentraExchangeShipper (SYSTEM, every minute + at boot)
  - prints which log files it found ("source 'msgtrk' ... N file(s)", "source 'iis' ... N file(s)")

How it behaves
  - Reads the files by byte offset and remembers where it stopped per file (bookmarks.json). A bookmark only
    moves after the SIEM accepted the lines (or they were saved in the local queue), so nothing is skipped.
  - Rotation is handled: new MSGTRK file per hour/day and new u_ex file per day start from the beginning; a
    file that shrinks (truncated / rolled in place) is re-read from the beginning; deleted files are forgotten.
  - The first run only replays files written in the last 60 minutes; older history is not uploaded.
  - The "#Fields:" header of every file is sent ahead of its lines (and again whenever it changes), so custom
    IIS field selections such as X-Forwarded-For are parsed correctly.
  - SIEM unreachable: batches wait in C:\ProgramData\SentraExchangeShipper\queue (up to 200 MB) and are replayed
    oldest-first with back-off (1, 2, 4 ... 15 minutes). When the queue is full the shipper pauses and the
    lines simply stay in the Exchange / IIS log files (which keep 30 days by default).
  - Load: a pass is bounded (50 000 lines, 8 MB per file); large backlogs are drained over several minutes.
  - Delete the lines it sent? No - the shipper only READS the files; Exchange and IIS keep managing them.

Verify Part 2:
  Get-Content C:\ProgramData\SentraExchangeShipper\logs\shipper.log -Tail 5
      -> "pass done: N line(s) shipped or queued, collector up, queue 0 file(s), M file(s) tracked"
  Get-Content C:\ProgramData\SentraExchangeShipper\bookmarks.json           -> one entry per log file with "offset"
  schtasks /Query /TN SentraExchangeShipper                                 -> Ready / Running
  powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Program Files\SentraExchangeShipper\sentra-exchange-shipper.ps1" -DryRun -Count 3
      -> prints the last 3 lines of the newest message tracking and IIS files exactly as they would be sent,
         and a summary of the files found; sends nothing.
  On the SIEM: Sources -> win-exchange -> this host shows events of type "exchange" (category email: receive /
  send / deliver / fail) and "iis" (category web, tags exchange-owa, exchange-ews ...) within 2 minutes of mail
  flow. Send yourself a test mail and look for it (subject appears as sha256:<hash>).

Common problems
  "collector unreachable: ConnectFailure"       TCP 443 to 10.0.0.10 blocked - open it (or set "Proxy").
  "TrustFailure"                                 collector certificate not trusted - import the issuing CA into
                                                 Local Computer -> Trusted Root (GPO). Never disable validation.
  "collector rejected the token (HTTP 401)"      wrong / rotated token - ask the SOC for the current token, then
                                                 re-run the installer with -TokenFile; the queue drains by itself.
  "no files found for ...MessageTracking..."     message tracking path differs - set "ExchangeInstallPath" or
                                                 edit "Sources[].Paths" in config.json (keep the wildcards).
  "ExchangeInstallPath not found"                run the installer with -ExchangeInstallPath "<path to V15>".
  queue growing                                  SIEM down or unreachable; data is safe up to 200 MB, then the
                                                 shipper pauses until the SIEM is back (lines stay in the logs).

Maintenance
  - Token rotation (SOC: sentra-siem-token rotate win-exchange): re-run BOTH installers with the new -TokenFile
    (config, bookmarks and queues are kept).
  - Upgrade: re-run the installers with the new scripts; they keep everything else.
  - Paths / options: C:\ProgramData\SentraExchangeShipper\config.json (Sources[].Paths, Proxy, ServerName,
    MaxFileAgeHours, QueueMaxMB ...). Changes apply at the next pass; no restart needed.
  - Re-send a file from the beginning: stop the task, delete that file's entry from bookmarks.json, start the task.

REMOVE
---------------------------------------------------------------------------------------------------
  cd "C:\Program Files\SentraExchangeShipper"   (or the folder you installed from)
  .\uninstall-exchange-shipper.ps1            removes task, program folder and C:\ProgramData\SentraExchangeShipper
                                              (kept if unsent batches remain; add -Force to delete anyway,
                                               -KeepData to keep config/token/bookmarks)
  .\uninstall-agent.ps1                       (agents\windows) removes the Windows agent the same way
  Ask the SOC to revoke the source token only when ALL Exchange servers are retired.

Questions: Smartshield / Zyberon support  (collector https://10.0.0.10 = soc.example.com, source id win-exchange).
