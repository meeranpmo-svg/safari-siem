# Moving the engines from Node.js to Python - gradually

Decision (Oct 2026): the engines move to Python **one module at a time**. Nothing is rewritten in one go, nothing is
switched off before its Python replacement is proven. The dashboards stay JavaScript (browsers run nothing else) and the
Windows agents stay PowerShell.

## How a module moves

1. **Port it** to `pyengine/<module>.py` - Python 3.8+, standard library only (nothing to install on the server), the same
   input and output, field for field. JavaScript quirks that change a result (rounding, empty values, dates without a time
   zone) are kept on purpose, so the two answer identically.
2. **Bridge it**: the Node.js engine calls `python3 -I pyengine/run.py` through `engine/pyengine.js` - one JSON request on
   stdin, one JSON answer on stdout. Credentials travel only on stdin (never the command line or the environment, which
   other users can read), the call has a time limit, the environment is minimal. A missing Python answers
   `missing_python` and the Node.js module answers instead, saying so (`engine: "node (python unavailable: …)"`).
3. **Prove it**: a parity test runs the Node.js and the Python module against the same simulated devices over real HTTP /
   HTTPS and requires identical answers and identical requests (`tests/storage-python.test.js` is the template), plus the
   module's own safety rules (read-only guard, TLS pinning, nothing sent to an untrusted device).
4. **Switch it on** by default, with a config switch back to Node.js (`storage.engine: "node"`).
5. **Remove the Node.js module** only after it has run on the live server without a difference for one full month.

Shared Python pieces: `pyengine/httpc.py` (HTTPS client with the same rules as `engine/discovery/httpc.js`), `pyengine/jscompat.py` (the JavaScript rules a port keeps: rounding, truthiness, dates, URL encoding), `engine/py-sources.js` (the bridge for a device reader: one line per module),
`pyengine/run.py` (the one entry point; each module adds its operations to `OPS`).

## New modules: Python first

A new engine module is written with its rules in Python from the start; there is no Node.js twin to prove parity with.
Node.js keeps what it keeps everywhere else: the route, the role check, validation at the boundary (`check.js`), the
audit record, the store write. Python decides; Node.js commits. When Python does not answer, the route answers 409 with
the reason (run the update) - it never guesses.
