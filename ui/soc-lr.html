Open an alarm to record why we missed it. Each review is saved on the alarm with your name and time (the SIEM's audit log keeps it too), so the weekly review and the exit report read from one record. A LogRhythm alarm counts as matched when one of our alerts overlaps it in time (± the match window) and either shares a user / IP / host with it or its rule is mapped to ours in lr_rule_map.

By LogRhythm rule

A LogRhythm rule with a low match rate usually needs either an equivalent rule here or a mapping in lr_rule_map (Settings → config) when our rule raises the same thing on a different entity.

By our rule

"Only ours" are detections LogRhythm did not raise in the same window. That is new coverage or a rule that is noisier than LogRhythm's - check before counting it as a gain.

By log source

LogRhythm's log source names and ours differ (theirs come from its Log Source list, ours from SIEM onboarding), so the same device may appear on two rows. Alarm counts here are detections, not log volume - compare event volume on the Log Sources page.

Import LogRhythm alarms

  1. In the LogRhythm Web Console open Alarms, set the date range (the last 30 days for the exit report) and clear the status filter so closed alarms are included.
  2. Export the grid as CSV (or save the Alarm API JSON). Keep the columns Alarm ID, Alarm Rule Name, Alarm Date, Priority / Risk score, Entity, Log Source and any user / origin / impacted IP or host columns.
  3. Drop the file below, check the column mapping and the time zone, then Import. Importing the same file again is safe: alarms already imported are skipped.
