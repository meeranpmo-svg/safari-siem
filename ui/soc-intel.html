Indicator lists

Loading…

Indicator lists (bad IPs, domains, file hashes) are files in the SIEM's intel folder (/var/lib/sentra-siem/intel/*.txt or *.csv, one indicator per line). Detection rules check every event against them; a match raises an alert. Hits count events that matched since the SIEM started. Files named allow-* or internal-* are reference lists, not threats. The SIEM picks up changed files by itself within 15 seconds; Reload now forces it.

Feeds - downloaded automatically

Loading…

Each enabled feed is downloaded on its schedule into the intel folder as feed-<id>.txt and used by detection within 15 seconds. The built-in feeds are free public lists (abuse.ch, Spamhaus) and start off. The SIEM server needs internet access to download them - if it goes through a proxy, set it once with install/netops-setup.sh --proxy. A failed download keeps the last good list. No internet? Paste or upload a list below (for example the CERT-SA / NCA IOC bulletins). An API key header is stored write-only and never shown again.

Tonight - what after-hours mode did

Between the end of the working day and the next morning, an alert at or above the page severity is e-mailed once to the on-call; nobody acknowledging it within the escalation time pages the escalation list. In prepare mode a case is opened with the alert's playbook so its containment steps are waiting for approval when someone arrives - the SIEM never executes an action, and only a named person can approve one. Alerts raised before the mode was switched on are never paged.
